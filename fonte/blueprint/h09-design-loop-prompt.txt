R: Build [GOAL: what you want, and how long or how big]. My bar: [one real thing that already does this brilliantly, one you can open: a site, a video or a doc]. If I have no bar, propose three, one line each, and take the hardest. If my bar is vague, ask me once for the exact page or file. My files: [design system, brand doc, script or draft].
I: First run a preflight, as a check and not a question. Fetch the bar now. Confirm you can render our output (screenshots for a site, a filmstrip of frames for animation, a PDF render for a doc). Report in one block what works, what is missing, and which critic goes blind. Then read the bar properly and write 5 to 7 checkable mechanisms to bar.md. Mechanisms, not adjectives. Show me the file and wait for my go.
S: Split the goal into three or four pieces. For each piece, run a builder, then three critics with fresh context who do not know how the builder worked. Write each critic's brief for this goal. Brief critic: judges my stated goal only and ignores looks. System critic: judges against design-system.md only. If I have none, say so and skip it. Craft critic: judges the render against bar.md only, never the code. It puts ours next to the bar with labels stripped, says which is better, and names the single biggest gap. Use the strongest model you have for this one. A weak one approves everything.
E: Critics are harsh. Praise is not useful. Each gives a pass or fail, never a score. All three must pass. Any fail goes back to the builder with the one biggest gap. Repeat each piece until all three pass. There is no fixed round count. I will stop you when I am happy. Keep a live progress page: each piece, each verdict, the gap history and the round count. Show rounds, not a token cost. You cannot see your own spend. Credit: the gauntlet loop is Matt Shumer's. The teardown, the three fixed critic roles and the preflight are added on top.
